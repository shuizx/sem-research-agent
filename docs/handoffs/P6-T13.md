## Actual behavior

`VRO_DATASET_PROFILE` is parsed only by central Settings; `--dataset-profile` overrides it. The
selected file is revalidated as the existing domain DatasetProfile before entering the CLI and
before each supervisor request. Code composition also validates an explicit setting. Invalid or
missing explicit input stops with `DATASET_PROFILE_INVALID_OR_MISSING`, without abstract fallback,
raw paths, parser payloads or model calls. Code does not open images or inspect a dataset root.
The existing `profile_dataset` remains the only profiler.

The application-local strict `SafeTargetProfile` projects channels, dimensions, class count,
sorted anonymous class-count values, aggregate split counts, split-strategy enum/proportions,
numeric resize and known normalization enum. Unknown numeric facts remain null, not invented.
Dataset IDs, display names, raw labels/IDs, group keys/IDs, holdouts, source configuration,
authorization text, original hashes/locations, sample paths and images are not forwarded.
`inspect_target_profile` supplies actual configured facts to the model, with
`configured_local_profile` provenance; the unchanged abstract SEM option is labeled
`abstract_default`. The prompt hash also binds these safe facts. The fixture planner now describes
the observed channel count instead of claiming every target is one-channel.

Context embeds only the typed safe target snapshot, not the source path. Content-addressed safe
copies below `target-profiles/` support trace provenance. Restart without explicit configuration
restores frozen statistics, not a new dataset inspection. Explicit configuration always
revalidates; changed safe facts clear old repository context and its last-result reference.
Changes only in excluded metadata do not alter the safe-facts fingerprint. New successful paper
selection also clears old repository context. `/clear` empties working context without deleting
artifacts; explicit process configuration remains active and revalidates on the next request.
The existing 64-KiB context bound and strict schema remain; the new field defaults to null for
older documents.

`/continue` and known paper-to-code follow-ups require a unique canonical current-paper GitHub
URL, then use the same supervisor, request budget and real human Code Gate. Missing/ambiguous
targets ask for clarification. Known current-repository requests use that repository, not an old
paper URL. Known current-paper requests resolve its arXiv identity; generic ambiguous continuation
asks which capability to use. Help/status/clear/exit remain deterministic.

The supervisor deterministically rejects repeated completed worker/target pairs, unrequested
Code expansion from a paper-only goal, ordinary explicit negatives (`不分析代码`, `no code`,
`without code`, `paper-only`) and Research expansion from an explicit repository-only request.
These are small ordinary scope guards, not a general natural-language permission parser.
Compound code requests and the independent three-distinct-delegation cap still work. Models
cannot approve Gates. The live URL safety check now distinguishes HTTPS URLs from drive paths.

The shared default-24 request budget covers live supervisor, Research, Code and direct-paper
schema corrections, including `/continue`. Trace observations contain only worker/status/ref and
a strictly checked stable reason code, plus delegation/model-call counts and target provenance.
Arbitrary reason text becomes `WORKER_FAILED`. Existing worker tool traces retain compact hashes,
not full tool transcripts. CLI emits concise Research/Code progress, stable failures and a final
summary/advice; raw JSON remains opt-in debug output.
