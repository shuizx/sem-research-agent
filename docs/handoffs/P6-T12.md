## Architecture and functional evidence

`LangGraphResearchPlanner` builds a real transient `StateGraph`: model → `ToolNode` → model.
The fixed tools are `search_papers`, `inspect_paper`, `submit_assessment`, `finish_research`.
The model sees the worker goal and fixed public problem/window, chooses search keywords, and
observes actual search results before deciding whether to refine or assess. There is no nested
per-paper LLM generation in this path. One assistant tool call per turn and 16 model turns are
allowed; no shell, repository access, training or approval tool is exposed.

At most two searches share the original request's total provider page/record budgets. Both use
the same persisted-watermark UTC window and existing normalization/deduplication functions.
At most five unique papers can be inspected/assessed. Submissions require previously inspected,
retrieved IDs, strict `PaperApplicabilityDecision`, exact source-field evidence excerpts and
URLs present in collected paper metadata. Handoff code links come only from selected provider
evidence, never from model-proposed links. Model/provider/schema/unsupported-tool failures stop
explicitly; no-results is a valid persisted outcome and advances the existing watermark.

The application-local `HardFilterDecision.mode=EVIDENCE_ASSESSED` distinguishes relevance assessment
from the legacy fixture prefilter. Missing Python/PyTorch/code metadata does not exclude a paper:
missing evidence becomes deterministic uncertainty/adaptation notes, not hard exclusion reasons.
The existing explicit arXiv path retains its single bounded structured assessment and now applies
the same soft-metadata interpretation. It retains summary, rationale, code status and provenance.
Legacy explicitly controlled five-stage sample dependencies keep their previous default pipeline.

Live conversational Research and standalone live Research compose the new planner over the
existing DashScope chat factory. Supervisor fixture/debug mode composes a labeled scripted
ToolAgent that uses the exact same ToolNode graph. The scripted transport is not a live relevance
judgment and consumes no live model budget, matching existing supervisor/Code fake behavior.

The same request default-24 `ModelCallBudget` callback charges live supervisor, Code and new
Research calls before logical provider invocation. The existing structured adapter now charges
each attempt, including explicit arXiv schema correction. Exhaustion propagates its stable explicit
budget error; provider transport retry configuration remains unchanged.

The final existing persisted candidate Gate, approval validation, approve/edit/reject handling and
checkpoint resume are reused. New-loop tests exercise the real Research graph and the supervisor's
inherited child checkpoint. Approved selection supplies fresh paper code evidence to compound Code;
rejection prevents Code. Ordinary resume does not repeat retrieval, assessment or model calls.
