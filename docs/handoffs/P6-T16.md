## Implementation and fixed acceptance

The installed LangGraph ToolNode wraps tool argument validation failures in `ToolInvocationError`
and retains their Pydantic `source`. The handler accepts that precise exception type only when
the tool is `submit_adaptation_advice`, every reported error is `too_long`, and each location
is one of the five declared top-level advice collections: `code_evidence`, `suggestions`,
`risks`, `items_to_verify`, `limitations`. Schema maxima come from the unchanged advice schema.
Short lists, nested/path errors, mixed errors, model validators and other tools are not
correctable. A run-local flag allows only one observation. All other failures retain the
existing explicit safe failure path.

The error ToolMessage contains only `errors` entries with declared field location, stable
`too_long` type and schema `max_length`. It contains no input values, validation context,
raw exception/model/source text or prompt transcript. It remains inside the same ToolNode
loop with the same bound tools and existing source-read state. The model must submit a new
complete typed advice value; the application never shortens its lists for it.

The failed submission contributes a value-free validation observation to the hash-only trace.
For this event, `arguments_hash` hashes `{}`, **not the original invalid model arguments**;
`output_hash` hashes the safe validation observation. This is not a complete raw call transcript.
Successful tool events retain their prior hash-only behavior. Failed overall analyses do not
write a completed trace, advice, report or result.

After a successful submit passes the existing schema, safety, prerequisite-tool and actual-read
path checks, the tools edge goes directly to END. This avoids an otherwise unnecessary eleventh
model call for the normal six-read correction case. First-valid runs also finish without a
separate model call to announce completion. No execution or approval authority changes.
